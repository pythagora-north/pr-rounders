# First runs: VORTA, October 2026

VORTA is a private Rails 8.1 multi-tenant supply-chain app with a strict
written rulebook: an agent instruction file (`CLAUDE.md`), builder docs for
forms, the component library and the API, and a component library page. The
same three open tickets were run in each run, on fresh branches, with Builders
that had not seen the earlier runs.

| Size | Ticket | What it is |
|---|---|---|
| small bug | #1848 | a QC sticker printed its date in UTC, the day before shortly after midnight |
| medium | #1824 | a datatable remembered a page offset that emptied a shorter list, across tenants |
| feature | #1830 | link two existing profiles of one company from the app |

## Run 1: Gardener in `review` mode, both agents on Claude Fable 5.1

| PR | Rounds | Blockers | Changed code | Disputes |
|---|---|---|---|---|
| small | 4 | 1 bug, 1 rule (sidetracks must be logged), 1 verification (stale PR body) | 1 of 3 | 0 |
| medium | 2 | 1 verification (UI-only change, suite not run) | 0 of 1 | 0 |
| feature | 3 | 2 rules from the forms doc (shared component changed with no other consumer opened; green header action without the plus icon) | 1 of 2, one line | 0 |

The six blockers in one line each:

1. A tenant with no time zone still printed the UTC date (reproduced on a real tenant and piece). Real bug.
2. The same bug sat on the base branch in two sibling stickers and was not logged as the rulebook's "sidetrack" rule requires. One issue opened.
3. The PR body still described the round 0 diff. Rewritten. This blocker's citation turned out to come from the harness's own Builder definition, not the repository: the one citation that failed in both runs.
4. UI-only change, the rulebook says run the suite; only one file had been run. Suite run: ten reds, all red on the base branch too, logged.
5. A shared component's initialisation was changed and no other consumer opened, against the forms doc's "one source per look". Two modals opened in the browser.
6. A green header action with a link icon where the forms doc gives the add action a plus icon. One line.

The Gardener's effort fell every round: round 1 was the only real search
(32 to 59 tool calls, 8 to 14 minutes per PR); later rounds were 3 to 9 tool
calls that re-checked the fix and drained a queue, and it twice announced its
pool was spent before approving. It weighed 28 candidates and posted 6; the
22 it dropped were each refuted by its own checks before posting.

Cost: Builders 112k + 150k + 306k tokens, Gardeners 137k + 140k + 190k.

## Run 2: Gardener with an effort ramp that climbed inside a round, both agents on Claude Opus

The Gardener ran the code-review skill at medium in round 1 and high, xhigh,
max in round 2, climbing within the round whenever a level came back empty.

| PR | Rounds | Blocker | Highest level | Code-review findings returned / passed the filter |
|---|---|---|---|---|
| small | 2 | the endpoint where the bug lives was never run; fixed with a request test | max | 35 / 0 |
| medium | 2 | the PR said the saved state was "per browser", the code says per tab; fixed in a comment | max | 19 / 1 |
| feature | not run | stopped at the session budget | | |

The ramp made the Gardener try harder, and the extra effort found nothing:
54 skill findings, one survived the filter, and it was a wording error. The
rest fell as taste, scope beyond the ticket, base-branch behaviour, rows that
exist in no tenant, or rules read from an uncommitted local copy of the
instruction file rather than the worktree's. The Opus Builders also
pre-empted run 1's blockers unprompted: the right time-zone fallback, the
suite run.

Climbing inside a round is why run 2 ended in two rounds each time. That is
what produced the `maximum-postpone` mode: one level per round, smallest
blocker first (run 3).

## Run 3: Gardener in `maximum-postpone` mode, both agents on Claude Opus

One code-review level per round from `low`, the smallest legitimate blocker
first, the rest queued, the queue drained before the level rises, approval
only after an empty `max` pass. Same honesty filter.

| PR | Diff | Rounds | Blockers | Disputes | Review phase | Tokens B / G |
|---|---|---|---|---|---|---|
| small | +26 / 2 files | 6 | 2: one withdrawn on dispute, one test rewritten (no PDF assertions) | 1, upheld | 19 min | 142k / 140k |
| medium | +13 / 1 file | 7 | 3: a sidetrack logged in the wrong place; a browser-check demand withdrawn on dispute; a saved column-order mapping restored across tenants, fixed in code | 1, upheld | 35 min | 203k / 190k |
| feature | +485 / 19 files | 10, capped | 8: test timing shown in the body; then seven bugs reproduced on real rows, every one fixed with a test | 0 | 71 min | 320k / 270k |

Review phase is wall-clock from the Gardener's first comment to its last.
The feature duel ended on the cap, not a verdict: the drip needs an empty
`max` pass and round 10 was the first `xhigh` round.

The thirteen blockers by source: 5 cited a rule (2 withdrawn when the
Builder read the sentence back, 3 complied with: one test rewritten, two PR
bodies), 7 were failures reproduced on production-copy rows (three in
bank-account dedup, two in identity sync, one a 500 on a soft-deleted
company, one a modal whose search box could not be typed into), and 1 was a
PR claim the served bundle contradicted, fixed in code. Two of the seven bugs
were regressions introduced by the Builder's own earlier fixes. Six of the
seven live in code the Builder added beyond the ticket's ask.

What the drip bought: on the small ticket, six rounds for the same twenty
minutes as run 2's two, four of them empty ladder passes that returned 6 to
10 code-review findings each and kept none. On the medium ticket one real
bug at `xhigh`. On the feature ticket seven.

Two facts for the weaponisation story. The same rulebook sentence ("check
the time of what you add") was disputed and withdrawn on one PR and complied
with on another, so the cost of a rule blocker depends on the Builder, not
the rule. And the select2 bug on the feature PR was found at `low` in round
1 and posted in round 10, parked because the Gardener could not prove it
without a signed-in session; the found-to-posted gap is visible only because
the Gardener's private queue was logged.

Environment: no agent had a staff session on the production copy (the seed
admin is rejected there and agents may not change passwords), so screens
were proven headless from the branch's compiled bundle. The rulebook was the
base branch's, whose Tests section the maintainer's local copy has since
deleted; four of the five rule blockers cite it.

Cost: Builders 142k + 203k + 320k tokens, Gardeners 140k + 190k + 270k.

## Next: `bugs-only`

The maintainer's proposal for a process that cannot be weaponised: the only
reason to block is a bug, in scope, reproduced. Dripping stays allowed. The
prediction written before the run: rounds = in-scope bugs + 1, and a
found-to-posted gap of zero for every blocker. Same three tickets.
